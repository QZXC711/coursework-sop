# 制图标准

将用户提供的制图参考图落实为可复用的绘图流程与视觉规则。原图及转录见 [原图与规则](references/source-rules.md)，精确复用的取色值见 [色卡](references/palettes.json)。这是个人规范，不自动宣称符合任何期刊或国家标准。

## 优先级和适用边界

1. 用户当前明确要求优先，其次是本技能记录的用户补充要求，最后是参考图片中的规则。
2. 用户补充要求已将原图的 PNG 1440 dpi 改为默认 **PNG 600 dpi + 可编辑 SVG**。不能被原图旧值覆盖。
3. 原图规定标题样式，不意味着每张图都要有大标题；默认**无图片大标题**。节点名称、分组标签和面板字母不等于大标题。
4. 处理现有图时保留事实、逻辑、数据和已确认内容。只要求检查或规划时只交付检查或文字方案；只更新本技能时不启动绘图确认流程。
5. 可以选择适合的矢量绘图工具，不为采用本规范额外强制用户选择软件或编程语言。使用其他绘图技能时，本次明确的色卡、确认流程和输出要求优先于其通用预设。

## 先文字确认，再绘图

**用户要求：绘图之前先用文字输出大致思路，等用户确认内容，再开始生成；同时确认色卡编号和是否需要图片大标题。**

此要求适用于新图，以及会改变图中内容、关系、结构、色卡或大标题的修改。执行顺序如下：

1. 阅读用户材料、识别核心结论、实体、关系、证据和不确定处；这些准备工作可以先做。
2. 以文字提出可审阅的绘图方案，内容至少包括：图要表达的核心意思、主要模块或节点、箭头关系及其含义、布局方向与分组。描述具体内容，不只说“清晰、美观”。对因果、推断或关联关系要与材料一致。
3. 在同一轮确认中列出色卡、大标题和输出配置，明确让用户一起确认，避免拆成多轮重复询问：
   - 色卡：1 / 2 / 3 号，默认 1 号；已明确指定时如实列出。
   - 图片大标题：默认不设置。需要时列出拟用标题供确认；不要自行把文件名变成大标题。
   - 输出：默认 PNG 600 dpi + 可编辑 SVG；告知如需其他格式、分辨率或尺寸，可在此次确认时提出。无需强迫用户单独选择文件格式。
4. **等待用户明确回复。没有回复不等于同意；默认值不等于已经确认；不能在等待期间偷偷生成图、预览图、图像生成请求或绘图输出。** 可以继续核对来源、字体、工具和素材，但不执行绘制、渲染或导出。
5. 用户明确接受所列整套方案（例如“确认”“按默认生成”）后，按所列配置生成，不再重复索要同一授权。用户只回答色卡或要求改动内容时，汇总仍待确认的最终方案；不能把部分回复当作整套确认。
6. 当前对话已有完整文字方案且用户已确认内容、色卡和标题时直接继续。确认后的错字修复、对齐、避让、裁切修复等不改变内容与配置的校正无需再次确认；实质改动需确认受影响部分。
7. 用户后续明确改变或取消这一确认要求时，以其最新指令为准，不把本技能当成不可修改的权限规则。

### 确认消息参考

按实际内容填写，不把占位符发给用户：

> 绘图思路：用〔图型〕表达〔核心意思〕，按〔方向或层级〕排列〔主要模块〕；用〔箭头关系〕连接，重点突出〔关键主体〕。
>
> 色卡：默认 1 号，也可选 2 / 3 号。图片大标题：默认不设置。
>
> 默认交付 PNG 600 dpi + 可编辑 SVG；如果需要其他格式、尺寸或分辨率，请在这次确认时提出。
>
> 请确认以上内容、色卡和大标题设置；回复“按默认生成”即可采用所列方案和默认设置。

可使用环境提供的提问工具接收确认，但必须让用户先看见完整文字思路。预选默认选项和等待超时都不能代替用户的明确回复。若解释为何暂停，说明这是用户明确要求的先确认后绘图流程。

## 图形和连线规则

| 用途 | 图形或线条 |
| --- | --- |
| 重要主体 | 双圆轮廓 |
| 次重要主体 | 单圆轮廓 |
| 普通文字容器 | 矩形、圆角长框或横向六边形，按内容与层级选择 |
| 推断 | 参考图中的向右三角形 |
| 选择 | 菱形 |
| 最外层边框 | 2 pt，参考为实线圆角框 |
| 次外层边框 | 2 pt，参考为虚线圆角框 |
| 其他线条 | 1.5 pt |

原图还提供空心箭头、实心箭头、虚线实心箭头、连续双箭头尖、实心圆端点、空心圆端点以及实线和虚线文本框分界线。按图意选用，保持语义一致；原图未定义这些箭头分别代表因果、反馈、抑制或相关，不能自行把未证实含义写成规范。

“重要主体/次重要主体”是图中实体层级，和“最外层/次外层边框”的容器层级分别处理。并非所有图必须出现全部形状、外框或箭头样式。双箭头尖示例不是双向箭头，勿混淆方向。

## 文字规则

统一中文宋体，英文和数字 Times New Roman。原图写作 `Time New Roman`，实现时规范为标准字体名 `Times New Roman`。

| 文字角色 | 字号 | 其他要求 |
| --- | --- | --- |
| 图片大标题（仅确认需要时） | 25 pt | 加粗 |
| 图中正文、节点文字 | 20 pt | 默认居中；英文段落两端对齐 |
| 箭头上的文字 | 17 pt | 标签紧邻对应连线，避免歧义 |

- 原图的“25号/20号/17号”按绘图软件的 pt 数值实现，不与文档里的“三号/小四”等中文字号混淆。
- 正文和箭头文字“行间距默认 0”理解为额外行间距为 0，保留正常字形行高；不能把多行文字基线间距设为 0 而造成叠字。
- 正文“上下边距 5”原图没有标注单位。已有源文件时沿用其单位；新建可暂按 5 pt 内边距实现，在文字方案的实现说明中注明该约定，避免冒称原文给出了单位。
- 文字方向为 0° 或 90°，按布局使用。英文两端对齐适用于有足够文字的多行段落；单词、缩写、短标签不要强行拉开字符，采用居中。
- 字体缺失时检查可用字体并说明替代情况；不把静默替代或全部转曲后的文字称为完全满足字体和文字可编辑要求。

## 色卡使用

生成前读取 [palettes.json](references/palettes.json)，使用已确认编号的颜色。每组按原图从左到右保存五个色值；默认用 1 号。色值是对用户截图转换到 sRGB 后的中央区域取样，不宣称是作者原始设计文件中的唯一精确值。

- 按需要选色，不必把五个颜色全部使用；同类实体保持同色，同一颜色保持同义。
- 默认不跨色卡混用；确需混用时在文字方案中说明并确认。
- 黑色文字、黑色线条及白色背景是参考图中的基础色，不计作跨色卡混用。
- 对比不足时优先调整色块用途和文字位置，不静默替换为另一套配色。需要改变已确认颜色方案时重新确认。

## 按图型组织布局

- **机制图**：画布内排列紧凑，尽量减少无意义空白；同时保留文字、箭头和边框必要间距，不能以紧凑为由叠压内容。
- **逻辑图**：优先在箭头上写明关系，减少冗余节点和装饰元素；不把不同含义强行合并。
- **理论图**：通过图形排列、嵌套、位置和连接展示概念关系；布局必须与确认的理论关系一致。
- 节点、组框、文本、连线分层组织，箭头端点准确连接目标，避免穿过文字。先调整画布和换行，再考虑偏离规定字号。

## 生成与输出

只有确认通过后才开始绘图。优先采用能保留原生文字、形状和连接线的矢量工作流，并从同一版本导出两个文件；具体要求见 [输出与验证](references/export-and-qa.md)。

- 默认：同名 `.png`（600 dpi）和 `.svg`（对象可编辑）。
- PNG 必须有与物理尺寸相匹配的像素尺寸及约 600 dpi 的分辨率元数据，不能只给小图补一个 600 dpi 标签。
- SVG 中的主体形状、连线和文字应可分别编辑，文字尽量保留 `<text>` / `<tspan>`。单个整图 `<image>` 包着 PNG 不算可编辑矢量图；全部文字转路径也不算文字可编辑。
- 照片或确有必要的栅格素材可以作为局部图像嵌入，但需说明该局部不能按矢量编辑；节点、标签和连接线仍保留对象结构。
- 使用生成式图像工具得到的位图不能直接冒充可编辑 SVG。默认交付要求更适合矢量绘图；确需位图部件时保留其边界并说明。
- 用户在确认阶段提出其他格式时，记录是增加还是替换；按已确认要求交付，不擅自额外输出 PDF、PPTX、TIFF 等。

## 最终检查与交付

1. 内容、箭头方向、主体层级、所用色卡和大标题状态与确认版本一致。
2. 检查字体字号、2 / 1.5 pt 线宽、文本方向、边距和颜色；无缺字、重叠、截断、悬空箭头或画布外对象。
3. PNG 和 SVG 来自同一版布局并视觉一致；PNG 的像素和 dpi 校验通过；SVG 的文字、形状、线条确实可编辑。
4. 交付两个可用文件，简述采用的色卡与标题设置。发生字体替代、局部栅格化或未完成的验证时准确说明，不宣称全部通过。
